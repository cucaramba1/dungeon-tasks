# Точечные чаты: анонсы ритуалов и событий (Dungeon Tasks)

Дата: 2026-10-12. Статус: черновик на ревью Некита.

## Цель

Бот сам читает конкретные Telegram-чаты, где конкретные люди пишут анонсы, и присылает Некиту запрос:
идёшь или нет. Переносы и отмены обрабатывает быстро. Некит уже «ниже по воронке»: эти события ему подходят
или он уже на них ходит. Поэтому фильтр афиши (интересы, веса категорий) здесь не нужен, нужен фильтр по автору.

Успех: Некит не пропускает перенесённое или отменённое занятие, не листает чаты ради расписания,
а любое событие из этих чатов можно записать в план одним тапом.

## Термины

- **Ритуал** = серия (еженедельная), в БД `tasks.is_habit=1` + `rrule` + `series_id`.
  Сейчас в боте один: «Настольная игра Dungeons & Dragons», каждую пятницу 18:30 (Нячанг).
- **Точечное событие** = анонс из точечного чата. Может стать разовой записью или ритуалом (по кнопке).

## Решение: вариант А (встраиваем в афишу)

Те же `events.py` и `events_feed`, отдельная секция `targeted` в `config/events.yaml`. Отличия от обычных каналов афиши:
фильтр по автору, разбор через `claude -p`, свой сценарий в боте. Позже LLM заменяется словарём (см. «Переход на словарь»).
Чаты из `targeted` из общей афиши исключаются (без дублей).

## Конфиг (схема)

```yaml
targeted:
  - id: -1003969606547
    name: Библиотерапия
    authors: [AlinaSnezhko]          # или author: channel
    fields: [book]                   # что доп. вытащить: book | variant | description
    series: null                     # или имя ритуала, к которому привязан чат
    until: null                      # дата окончания (йога: 2026-10-31)
    attend_days: null                # дни, на которые ходит Некит (йога: [TU, SU]); остальные анонсы игнорируются
    topics: null                     # для форума: {3: outdoor, 132: indoor}
```

## Поток данных

```
 час ──> collect_targeted():
          по каждому чату: get_history (новые id > ev_last), оставить посты от authors
              пусто ──> LLM не вызываем
              есть  ──> ОДИН claude -p на чат: новые посты + открытые события чата (контекст)
                          │  ответ по JSON-схеме
                          ▼
          events_feed: kind=announce | move | cancel, поля, статус
                          │
        ┌─────────────────┴──────────────────┐
   announce                              move / cancel
   копим до подборки                     сразу (на этом же часовом тике)
   10:00 · 16:00 · 22:00                 бот применяет и сообщает с кнопкой «↩»
```

Контракт ответа LLM по каждому посту: `kind` (announce | move | cancel | none), `title`, `date`, `time`,
`place`, `fields` (book, variant, description), `ref_event_id` (для move и cancel: какое известное событие),
`confidence`. Дата и время в локальной таймзоне Нячанга. Посты без текста (опросы) пропускаются.

Реальные примеры, на которых проверяем разбор (канал «Цели и привычки»):
- «Всем привет! Темой завтрашней встречи будет … 21.09.2026 11.00 Место… Ценность: Донат + напиток» → announce.
- «Завтрашней встречи по целям не будет… » → cancel.
- «Следующая встреча пройдет 19.10.2026 в 11.00» → announce (следующая дата, не перенос).

## Поведение бота

**Анонсы** копятся и уходят подборкой в 10:00, 16:00, 22:00 (карточка на пункт). Пустая подборка не отправляется.
Если анонс на ближайшие 3 часа, он уходит сразу, не ждёт подборки.

Кнопки на карточке:
- чат привязан к ритуалу (D&D, йога): `✅ Подтвердить` (занятие этой недели) · `❌ Пропускаю`;
- остальные: `✅ Иду` (разовая запись) · `🕯 В ритуал` (серия на каждую неделю) · `❌ Мимо` · `✏ Поправить`.

В карточке: название, дата и время, доп. поля (книга, indoor/outdoor, описание), ссылка на пост,
пересечение с планом одной строкой. Не ответил: одно напоминание через 2-3 часа, дальше запись остаётся в PWA.

**Перенос.** Если `ref_event_id` найден и исходная дата известна, бот сразу меняет `due_at`
**ближайшей открытой записи серии** (серия и `rrule` не трогаются) и пишет:
«Перенёс D&D с пт 16.10 18:30 на сб 17.10 18:30. [↩ Вернуть]». Если исходная дата неоднозначна или
`confidence` низкий, бот спрашивает, какое событие имеется в виду.

**Пропуск занятия серии (решает Некит).** Любой пропуск ритуала из этих чатов (кнопка «❌ Пропускаю» или
«Отмена» от Некита) спрашивает причину:
- `🚫 Прогул` → штраф `skip_penalty_hp` (по умолчанию 20 HP, значение в `config`), занятие помечается missed;
- `📌 Важная причина` → без штрафа: занятие просто переносится (бот предлагает новую дату из ближайших анонсов,
  иначе остаётся «без даты» в плане), серия не ломается, стрик не сгорает.

**Отмена от организатора** («встречи не будет»): вины Некита нет, штрафа нет, вопрос про причину не задаётся.
Запись этой недели снимается, следующее занятие серии остаётся, бот сообщает. Кнопка «↩» возвращает.

**Йога.** Занятия 3 раза в неделю: вторник, пятница, воскресенье. Некит ходит во вторник и воскресенье,
пятница занята D&D. Ритуала в боте нет, поэтому по первому анонсу бот предлагает завести ритуал «Йога»:
`rrule` `FREQ=WEEKLY;BYDAY=TU,SU;UNTIL=2026-10-31` (время из анонса). Анонсы на пятницу бот игнорирует без вопросов
(`attend_days: [TU, SU]` в конфиге чата). После `until` анонсы чата игнорируются.

## Данные

`events_feed` получает поля (миграция `ALTER TABLE`, без потери данных):
`author`, `kind`, `extra` (JSON: book, variant, description), `status`
(new | pending | accepted | declined | moved | cancelled), `task_id`, `notified_at`, `llm_raw`.
`llm_raw` + итоговое решение Некита = обучающая выборка для перехода на словарь.

## PWA: раздел «Афиша ритуалов»

Список ближайших анонсов по датам: название, время, доп. поля, ссылка на пост, чекбокс «записаться».
Чекбокс делает то же, что «Иду» в боте (создаёт задачу). Для привязанных к серии чатов отмечает занятие этой недели.
Эндпоинты добавляются в `web.py` рядом с существующими (`/api/...`), авторизация как у остальных.

## Ошибки

- telegram-mcp не отвечает: используем существующий `_heal_tgmcp`; посты не помечаются обработанными, повтор через час.
- `claude -p` недоступен или лимит: посты остаются необработанными, одно уведомление Некиту, не на каждом тике
  (как в `coach.ClaudeUnavailable`).
- LLM вернул дату в прошлом или `confidence` низкий: карточка уходит с пометкой «проверь», кнопка «✏ Поправить».
- Дубли: один анонс в нескольких чатах склеивается по существующему `dedup_key`.

## Первый запуск

Только новые сообщения с момента подключения + последние 7 дней (чтобы Некит сразу увидел, как это работает).
Старые посты не рассылаются по одному: идут в первую подборку, максимум 10 карточек.

## Переход на словарь (позже)

Когда по `llm_raw` + решениям накопится выборка, правила автор → тип/поля выносятся в `config/events.yaml`,
и LLM вызывается только на постах, которые словарь не разобрал.

## Тесты

- Фикстуры из реальных постов (примеры выше + анонсы остальных чатов, нужно собрать при реализации).
- LLM в тестах подменяется заглушкой с записанным ответом.
- Юнит-тесты: фильтр автора и топиков, привязка к серии, перенос ближайшей записи без сдвига серии, прогул (−20 HP) и важная причина (без штрафа), отмена организатора,
  игнор пятничной йоги, расписание подборок.
- Ручная проверка перед включением: прогон на последних 7 днях всех чатов, сверка с тем, что Некит видит глазами.

## Вне объёма (YAGNI)

Отправка сообщений в чаты, регистрация на мероприятия, оплата, парсинг опросов, веса категорий для точечных чатов.

## Открытые вопросы для реализации

1. Время йоги берётся из первого анонса; `rrule` (вт, вс) подтверждается Некитом.
2. Как `rollover` и `_spawn_next` в `services.py` ведут себя при переносе и снятии открытой записи серии:
   не проверено. Риски: штраф −10 HP за «пропущенный» ритуал при отмене организатором, потеря следующего экземпляра,
   стрик при «важной причине». Проверить и покрыть тестами. Штраф за прогул 20 HP: сейчас в игре −10 за несделанный
   ритуал, точка применения нового штрафа (`game.py`) определяется при реализации.
3. Для каналов без автора (покер, лекции) «автор» = канал; проверить поле `username` в ответе `get_history`.
