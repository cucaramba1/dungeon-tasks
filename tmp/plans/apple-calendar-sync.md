# Dungeon Tasks → Apple Calendar (CalDAV, одностороннняя синхронизация)

## Что синкаем
Задачи из таблицы `tasks`, у которых есть `due_at` (дата/время):
- обычные задачи с дедлайном/временем — один VEVENT на задачу;
- ритуалы/привычки и повторяющиеся задачи с `rrule` — один «мастер»-VEVENT с RRULE на всю серию (не плодим события на каждое повторение, т.к. в БД каждое повторение — новая строка через `_spawn_next`);
- пункты недельного плана (`/plan`) синкаются автоматически, т.к. в конце шага 4 они становятся обычными строками в `tasks`.

Задачи без даты (чистый инбокс, бэклог) в календарь не идут — им нет смысла там быть.

Направление: только Dungeon → Calendar. Ручные правки в Calendar.app не читаются и будут затёрты при следующей синхронизации этой же задачи.

## Технически
- iCloud CalDAV (`https://caldav.icloud.com`), библиotека `caldav` (+ `icalendar` для сборки VEVENT).
- Авторизация: Apple ID + **app-specific password** (генерируется на appleid.apple.com, обычный пароль CalDAV не примет). Хранится в `.env`.
- Отдельный календарь «Dungeon Tasks» — создаётся автоматически при первом запуске, если его нет. Так ручные личные события не смешиваются и если что сломается — легко почистить, удалив один календарь.

## Изменения в коде

1. **Зависимости** (`pyproject.toml`): `caldav`, `icalendar`.
2. **`.env` / `.env.example`**: `ICLOUD_APPLE_ID`, `ICLOUD_APP_PASSWORD`, `ICLOUD_CALENDAR_NAME` (по умолчанию «Dungeon Tasks»). Если `ICLOUD_APPLE_ID` пуст — синк полностью выключен, без ошибок.
3. **`dungeon/db.py`**: миграция — добавить `tasks.caldav_uid TEXT` (для одиночных задач) и новую таблицу `calendar_series(series_id INTEGER PRIMARY KEY, uid TEXT)` (для ритуалов/повторов). Плюс `calendar_outbox(id, task_id, action, requested_at)` — очередь отложенной отправки, чтобы не дёргать iCloud синхронно из обработчика Telegram-сообщения.
4. **`dungeon/caldav_sync.py`** (новый модуль, весь сетевой код тут, синхронный — вызывается через `asyncio.to_thread`):
   - подключение и получение/создание календаря;
   - `upsert_task(task)` — одиночная задача: создать/обновить VEVENT по `caldav_uid`;
   - `upsert_series(series_id, task)` — мастер-событие с RRULE (конвертация строки вида `FREQ=WEEKLY;BYDAY=FR` в параметры VEVENT, это уже совместимый формат);
   - `delete(uid)`.
5. **`dungeon/services.py`**: при любом изменении, затрагивающем `due_at`/`rrule`/`title`/статус (`create_parsed`, `set_due`, `edit_from_text`, `rename`, `done`, `delete`, `toggle_habit`) — если это не строка со `source='repeat'` (она покрыта мастер-событием серии), кладём запись в `calendar_outbox` вместо прямого сетевого вызова.
6. **`dungeon/scheduler.py`**: в `tick()` — новый пункт, раз в тик разбирает до N записей из `calendar_outbox` через `asyncio.to_thread(caldav_sync....)`, пишет `caldav_uid`/`calendar_series.uid` обратно, при ошибке (нет сети, протухший пароль) оставляет запись в очереди и логирует — без падения тика.
7. **Тесты**: `tests/test_caldav_sync.py` — конвертация rrule-строки в параметры VEVENT, логика «когда класть в outbox» (мок сети, без реального запроса к iCloud).
8. **README.md**: раздел «Apple Calendar» — как сделать app-specific password и что писать в `.env`.

## Проверка перед «готово»
- `uv run pytest` зелёный;
- вручную: создать задачу с дедлайном через бота → в течение ~15 сек событие появляется в календаре «Dungeon Tasks» на Mac/iPhone;
- создать ритуал «каждый вторник в 9 йога» → в календаре одно повторяющееся событие, а не куча отдельных;
- выполнить/удалить одиночную задачу → событие исчезает из календаря;
- выключить `ICLOUD_APPLE_ID` в `.env` → бот работает как раньше, синк молча не активен.
